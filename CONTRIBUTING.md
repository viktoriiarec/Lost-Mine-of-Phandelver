# Правила разработки

## Рабочий цикл

1. Выбрать одну небольшую задачу с проверяемым результатом.
2. Создать ветку от актуальной `main`.
3. Реализовать задачу без несвязанных изменений.
4. Проверить компиляцию Unity и тесты.
5. Открыть pull request с результатом и способом проверки.
6. После проверки объединить изменения в `main`.

## Когда задача готова

- проект компилируется без ошибок;
- поведение воспроизводится по короткой инструкции;
- игровые правила не находятся в UI;
- чистая логика покрыта тестами;
- сторонние ассеты внесены в `THIRD_PARTY_NOTICES.md`;
- документация соответствует текущему поведению.

## C# и Unity

- Пространство имён: `LostMineOfPhandelver` и вложенные пространства.
- Один основной публичный тип на файл.
- `PascalCase` для типов, методов и свойств; `camelCase` для параметров и локальных переменных; `_camelCase` для приватных полей.
- MonoBehaviour отвечает за жизненный цикл Unity; правила остаются в обычных C#-классах.
- UI вызывает игровые системы и отображает их результат.
- Не использовать глобальные менеджеры без конкретной ответственности.
- Диалог, бой, сохранение и UI развиваются как отдельные модули.

## Контент

- Не копировать текст, карты или иллюстрации опубликованного приключения.
- Использовать собственные пересказы, тестовые данные и лицензированные ассеты.
- Для каждого стороннего ресурса фиксировать автора, URL и лицензию.

## Коммиты

Формат: `type: краткое действие`.

Примеры:

- `feat: add d20 ability checks`
- `fix: calculate negative ability modifiers`
- `docs: describe goblin ambush slice`
- `test: cover difficulty class boundary`

Типы: `feat`, `fix`, `docs`, `test`, `refactor`, `chore`.
